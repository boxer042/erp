# 부가세 회계 기초 — Q&A 정리

> 2026-05-13 대화 정리. 일반과세자 기준. 시스템 분석 + 회계 원리 + 실무 적용까지.

## TL;DR (시간 없으면 이것만)

1. **부가세는 비용도 수익도 아니다.** 일반과세자에게는 임시 자산(대급금) / 임시 부채(예수금)일 뿐.
2. **재무제표·손익·자본·마진은 공급가액 기준만** 보면 된다. 부가세는 등장하지 않음.
3. **부가세 납부는 부채 상환** — `Expense` 에 절대 넣지 말 것 (이중 차감됨).
4. "내가 쓸 수 있는 돈" = 공급가액 기준 누적 자본. 통장 잔액과는 다름 (부가세 부채만큼 차이).
5. **운영상 부가세는 별도 추적은 필요** — 청구·결제·신고 시점에. 단, 손익엔 안 닿게.

## 1. 핵심 개념 — 부가세는 "맡아두는 돈"

### 1.1 매입 시 (거래처에 부가세 지급)

```
공급가 1,000,000 + VAT 100,000 = 1,100,000 송금

분개:
  (차) 상품              1,000,000   ← P&L: 매출원가/재고
       부가세대급금        100,000   ← 자산 (국가가 돌려줄 돈)
                  (대) 현금        1,100,000
```

**부가세대급금 = 자산. 비용 아님.**

### 1.2 매출 시 (고객으로부터 부가세 수취)

```
공급가 2,000,000 + VAT 200,000 = 2,200,000 수금

분개:
  (차) 현금              2,200,000
                  (대) 매출           2,000,000   ← P&L: 매출
                       부가세예수금     200,000   ← 부채 (국가에 낼 돈)
```

**부가세예수금 = 부채. 수익 아님.**

### 1.3 분기 부가세 신고

```
부가세예수금 200,000 − 부가세대급금 100,000 = 100,000 납부

신고:
  (차) 부가세예수금  200,000
                 (대) 부가세대급금   100,000
                      미지급세금     100,000   ← 부채 계정

납부:
  (차) 미지급세금   100,000
                 (대) 현금          100,000   ← 자산 ↓ + 부채 ↓
```

**비용 계정 안 거침. P&L 영향 0.**

## 2. "그럼 재무제표는 어떻게 나오나" — 손익계산서 예시 (2026 Q1)

**모든 금액 공급가액 기준 (₩ 단위).**

| 구분 | 항목 | 금액 |
|---|---|---:|
| **매출액** | 판매상품 | 80,000,000 |
| | 수리 | 15,000,000 |
| | 임대 | 5,000,000 |
| | 합계 | **100,000,000** |
| **매출원가** | (FIFO 실제 원가) | (55,000,000) |
| **매출총이익** | | **45,000,000** |
| **판관비** | 임대료·인건비·배송비·포장재·광고·채널수수료·카드수수료·공과금·기타 | (38,000,000) |
| **영업이익** | | **7,000,000** |

**부가세는 어디에도 안 보임.** 매출 옆에 부가세 10M 더 안 붙고, 매입 옆에 매입세액 안 붙고, 부가세 납부도 비용에 안 들어감. 이게 정상.

### 재무상태표에 잠깐 보이는 자리

분기말 신고 전:
- **자산**: 부가세대급금 (분기 중 거래처에 낸 매입 VAT)
- **부채**: 부가세예수금 (분기 중 고객에게 받은 매출 VAT)

분기말 신고·납부 후 → 둘 다 0 으로 상계, 차액만 현금 ↓.
**자본/이익잉여금엔 영향 없음.**

## 3. 사고실험 — 자본금 1,000만으로 시작

가정: 1분기 동안 매입 2,000만(+VAT 200) / 매출 3,000만(+VAT 300) 거래.

| 시점 | 이벤트 | 현금 흐름 | 통장 잔액 |
|---|---|---:|---:|
| 0 | 자본금 납입 | +10,000,000 | 10,000,000 |
| 1 | 매입 + VAT 22M 송금 | -22,000,000 | -12,000,000 (외상 가정 안 함) |
| 2 | 매출 + VAT 33M 수금 | +33,000,000 | 21,000,000 |
| 3 | 부가세 신고 (예수금 300 − 대급금 200 = 100 부채 확정) | 0 | 21,000,000 |
| 4 | 국가에 100만 납부 | -1,000,000 | **20,000,000** |

### 부가세만 떼서 보면

| 시점 | 이벤트 | 부가세 현금 |
|---|---|---:|
| 1 | 매입 VAT 200 송금 | -2,000,000 |
| 2 | 매출 VAT 300 수금 | +3,000,000 |
| 4 | 국가에 차액 100 납부 | -1,000,000 |
| | **합계** | **0** |

**부가세 사이클이 닫히면 현금에 영향 0.** 통장 잔액이 10M → 20M 으로 늘어난 건 매출이익(공급가 3,000 − 매입 2,000 = 1,000만) 때문이지 부가세 때문이 아님.

## 4. 부가세 납부는 경비? — 아니다

### 왜 경비가 아닌가

매출 시 받아둔 부가세를 국가에 그대로 넘기는 거니까 내 비용이 아님. **부채 상환.**

만약 경비로 잡으면:
- 매출 → 공급가액만 (부가세 분리)
- 매입 → 공급가액만 (부가세 분리)
- 부가세 납부 → 경비 ❌

= **같은 돈을 두 번 빼는 이중 차감**. 손익이 실제보다 낮게 나옴.

### 시스템에서 어떻게

`Expense` 모델 category 중 **어디에도 넣지 말 것** (OTHER 포함). 어느 카테고리에 넣든 P&L 로 새어 나감.

권장:
- **단순 운영**: ERP 에 기록 안 함. 통장 거래내역으로만 남기고, 세무 신고는 홈택스/세무사 별도 처리.
- **정식**: `TaxPayment` 별도 도메인 신설 (`kind: VAT/INCOME_TAX`, `amount`, `paidAt`, `periodStart/End`). P&L 과 격리.

지금 규모에선 단순 운영 권장. 부가세 자료(예수금/대급금 합계)만 시스템에서 뽑아서 세무사에게 전달.

## 5. P&L 에 안 들어가는 다른 출금들 (같은 원리)

| 출금 항목 | 비용? | 정체 |
|---|:---:|---|
| 부가세 납부 | ❌ | 부채 상환 (고객한테 받아둔 돈) |
| 원천세 납부 | ❌ | 부채 상환 (직원 세금 대신 보관) |
| 4대보험 (회사부담분) | ✅ | 복리후생비 |
| 4대보험 (직원부담분) | ❌ | 부채 상환 (월급에서 떼서 보관) |
| 법인세 납부 | ❌ | 이익잉여금 차감 (이미 발생한 이익에서) |
| 차입금 원금 상환 | ❌ | 부채 상환 |
| 차입금 **이자** | ✅ | 이자비용 |
| 사장님 개인 인출 | ❌ | 자본 차감 (가지급금) |

**대원칙**:
> **이 돈이 "누구를 위한 돈인가?"**
> - 사업 운영을 위한 지출 = **비용**
> - 누군가에게 맡아둔 돈을 돌려주는 것 = **부채 상환** (비용 아님)
> - 이미 발생한 이익에서 빠져나가는 것 = **자본/잉여금 차감** (비용 아님)

## 6. 통장 잔액 vs "내가 쓸 수 있는 돈"

두 가지 다른 숫자임을 구분해야 함.

| 질문 | 어느 기준? |
|---|---|
| "통장에 실제로 얼마 찍혀 있나?" | 부가세 **포함** (실제 입출금된 돈) |
| "그 중 내가 진짜 쓸 수 있는 돈은?" | **공급가액 기준** (또는 통장잔액 − 부가세 미납 부채) |

### 예시 (분기말 통장 잔액 2,100만, 그 중 진짜 내 돈?)

```
통장 잔액              2,100만
− 부가세 예수금           300만   ← 곧 국가에 낼 돈
+ 부가세 대급금           200만   ← 곧 환급/상계받을 돈
────────────────────────
진짜 내 돈              2,000만
```

처음부터 공급가액으로만 계산:
```
시작 자본 1,000 + 매출 3,000 − 매입 2,000 = 2,000만   ← 같은 답
```

### 시스템 관점에서

- **뷰 1 — "내 사업이 얼마나 잘 되고 있나"** (손익·자본·자기자본 성장):
  - 공급가액 기준만. `Order.subtotalAmount`, `Incoming.totalAmount - taxAmount`, `Expense.amount`(과세는 ÷ 1.1) 누적.
  - **이게 손익계산서**.

- **뷰 2 — "지금 통장에 얼마, 다음달 얼마 들어올 예정"** (현금흐름):
  - 부가세 포함 + 결제 시점 추적. 매출채권/매입채무, 부가세 미납 부채까지 다 반영.
  - 손익과 분리해서 별도 리포트.

⚠️ 손익이 흑자여도 통장이 비는 경우 가능 (외상 매출 입금 지연, 카드 매출 입금 지연 등). **흑자도산** 의 원리.

## 7. 현재 시스템 (ERP) 분석 — 부가세 처리 현황

### 7.1 잘 되어 있는 부분 ✅

- `Incoming.taxAmount`, `Order.taxAmount` 부가세 별도 저장
- 모든 가격 필드는 **세전(공급가액) 기준 저장** (`Product.listPrice`, `OrderItem.unitPrice` 등)
- `Incoming.shippingCost`, `IncomingCost`, `SellingCost` 에 `isTaxable: boolean` 분리
- `SupplierLedger` / `CustomerLedger` 거래액은 **부가세 포함 청구총액**으로 기록

### 7.2 아쉬운 부분 ⚠️

- `SupplierPayment` / `CustomerPayment` 에 거래 외래키 없음 → **거래 단위 부분결제 추적 불가**
- 결제 종류 enum 없음 → "공급가액만 결제 vs 부가세만 결제" 구분 불가
- `TaxInvoice` 별도 모델 없음 → `Order.taxInvoiceRequested` / `taxInvoicedAt` 마킹만 존재
- 부가세 신고용 집계 리포트 없음

### 7.3 부가세 후납 처리 방안 (3단계 옵션)

| 옵션 | 내용 | 작업량 |
|---|---|---|
| **A. 현상 유지** | 결제 메모에 "공급가액만 입금" 키워드. 잔액은 거래처 전체 잔액으로 추적. | 0 |
| **B. 결제 종류 enum 추가** | `PaymentKind` (MIXED/SUPPLY_ONLY/VAT_ONLY). 신고용 보고 가능. | 소 |
| **C. 거래 단위 부분결제** | Payment 에 `incomingId/orderId` 추가. 거래별 미수/미지급 + 부가세 후납 잔여 추적. | 대 |

**추천**: B 부터 시작. C 는 B2B 비중 커질 때.

## 8. 손익계산서 데이터 매핑 (구현 시 참고)

| 항목 | 데이터 출처 (공급가액 기준) |
|---|---|
| 판매상품 매출 | `Order.subtotalAmount` 합계 (COMPLETED + repairTicketId=null + rentalId=null) |
| 수리 매출 | `Order` 중 `repairTicketId != null` |
| 임대 매출 | `Order` 중 `rentalId != null` |
| 매출원가 (FIFO) | `LotConsumption.quantity × unitCost` 합계. 폴백: `OrderItem.unitCostSnapshot × quantity` |
| 채널수수료 | `OrderItem.channelCommissionRateSnapshot × totalPrice` |
| 카드수수료 | `OrderItem.cardFeeRateSnapshot × totalPrice` (카드결제 한정) |
| 일반 판관비 | `Expense.amount` (과세면 ÷ 1.1) — category 별 집계 |
| 부가세예수금 | `Order.taxAmount` 합계 (기간 내) |
| 부가세대급금 | `Incoming.taxAmount` 합계 + 과세 `Expense × 0.1 ÷ 1.1` |

### 교환 새 주문 (-EX) 제외
마진 리포트와 동일하게 `exchangedFromOrders: { none: {} }` 필터로 매출 중복 방지.

### 환불·매출취소 처리 (V3 — 총액주의 + 부분환불 비례차감)
- 매출은 **발생 시점 기준** (모든 PREPARING~ 단계 + 반품 진행 + RETURNED/EXCHANGED 포함)
- 환불·취소는 **별도 매출 차감 라인** 으로 표시:
  - `RETURNED` → 반품 차감
  - `EXCHANGED` → 교환 차감
  - `paymentStatus=SALES_CANCELLED` → 매출 취소 차감 (외상 반품)
  - `OrderItem.refundedAmount > 0` → 부분 환불 차감
- **전액 차감** 주문의 매출원가/수수료/판매비용은 100% 차감
- **부분환불** 의 수수료·판매비용·매출원가(unitCostSnapshot fallback 시)는 환불 비율로 비례 차감
- `-EX` 새 주문은 손익계산서에선 매출 포함 (원본 EXCHANGED 차감과 짝맞춤). 마진 리포트는 별개로 `-EX` 제외 유지.

## 9. 한 줄 요약

> **경영 판단 = 공급가액만 / 청구·결제·신고 = 부가세 분리 추적 / 부가세 납부 = 부채 상환 (비용 아님).**
